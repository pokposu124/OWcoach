# 코치 검수 방법

## 1. 분석 결과 검수 (영상별)

1. 분석을 실행하면 `analyzer/runs/<run_id>/report.html` 이 생긴다. `runs/<run_id>/` 폴더 전체를 받아 Chrome/Edge/Safari로 `report.html` 을 연다. (프록시 영상과 근거 프레임이 같은 폴더에 있어야 함)
2. 상단에 빨간 "모의(mock)" 배너가 있으면 실제 AI 결과가 아니다. 검수하지 않는다.
3. 각 피드백 카드에서:
   - 시간 버튼(▶)이나 근거 프레임을 누르면 해당 시간으로 영상이 이동한다.
   - **관찰 사실**: 화면에서 정말 그런 일이 있었는지 → 정확 / 일부 틀림 / 틀림 / 확인 불가
   - **판단**: 기준을 올바르게 적용했는지 → 동의 / 부분 동의 / 반대
   - **시간 정확도**: 정확 / ±3초 이내 / 틀림
   - **기준 수정 필요**: 판단이 틀린 원인이 기준(heroes/*.yaml) 문구 때문이면 체크하고 코멘트에 수정안을 적는다.
   - "참고·보류" 배지는 시스템이 단정하지 않기로 한 항목이다. 보류가 맞았는지도 코멘트로 남긴다.
4. 하단 "놓친 장면"에 AI가 놓친 중요한 장면을 `mm:ss 설명` 으로 적는다.
5. "제외된 항목"을 펼쳐 시스템이 버린 피드백 중 살렸어야 할 것이 있는지 본다.
6. **검수 결과 저장**을 누르면 `coach_review.json` 이 내려받아진다. 이 파일을 `runs/<run_id>/coach_review.json` 으로 넣어 개발자에게 전달한다. (모델·프롬프트·기준 버전이 함께 기록됨)

## 2. 코칭 기준 검수 (영웅별)

`analyzer/heroes/<hero>.yaml`

- 모든 기준은 `status: draft` 로 시작한다. 코치가 문구·good/bad signs·`cannot_judge_when` 을 확인하면 `status: approved` 로 바꾸고 `source` 에 근거(코치 이름/자료)를 적는다.
- 판단할 수 없는 상황은 `cannot_judge_when` 에 추가한다. 모델은 해당하면 판단을 보류한다.
- 쿨다운·사거리 같은 **수치는 `numeric_facts` 에만**, 공식 패치노트 URL(`source`)과 `patch_version` 을 반드시 함께 적는다. 확인 안 된 수치는 넣지 않는다.
- 기준을 고치면 `profile_version` 을 올린다. 결과 JSON에 버전이 기록되어 어떤 기준으로 나온 결과인지 추적할 수 있다.
- 검수된 기준만 단정적으로 보여주려면 `config/analysis.yaml` 의 `require_approved_criteria_for_assertive: true`.

## 3. 품질 지표 (여러 영상 검수 후)

`coach_review.json` 들을 모아 다음을 본다.

- 관찰 사실 정확도 = 정확 / 전체 (목표 예: 90% 이상)
- 판단 동의율 = 동의 / 전체
- 시간 정확도 (±3초 이내 비율)
- 놓친 장면 수, 보류가 과도했는지
- 같은 유형의 오인식이 반복되면(예: 쿨다운 숫자) 그 항목에만 전용 처리(HUD 크롭 + OCR 등)를 제안한다.
