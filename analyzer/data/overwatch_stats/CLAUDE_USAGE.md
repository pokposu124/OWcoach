# Claude Code에 전달할 지시

이 폴더의 `README.md`, `coverage_report.md`를 먼저 읽고, `overwatch_heroes.json` 또는 `overwatch.sqlite`를 오버워치 AI 피드백 시스템의 지식원으로 연결해 주세요.

## 조회 계층

영웅은 `hero_id`로 식별합니다. 표시명에는 `name_ko`를 쓸 수 있습니다. 스킬은 `ability_id`로 식별하며, 영문 이름과 변형 조건을 유지하세요. JSON 전체를 매 프레임 LLM에 전달하지 말고 해당 경기의 영웅·스킬·규칙만 조회하세요.

최소 도구 인터페이스:

```text
get_hero_stats(hero_id, mode="5v5_role_queue")
get_ability_stats(hero_id, ability_id)
get_perks(hero_id)
get_review_items(hero_id)
```

조회 결과에는 값뿐 아니라 단위, 적용 조건, 출처 고정 개정 링크, `wiki_only`/검증 상태와 `review_required`를 함께 반환하세요. 필요하면 `query.py`를 읽기 전용 참조 구현으로 쓰세요.

## 피드백 생성 규칙

1. 경기의 패치와 모드가 데이터 수집본에 맞는지 확인합니다. 다르면 확인이 필요한 전제로 표시합니다. 문서 편집 시각을 패치 번호로 쓰지 않습니다.
2. 기본 수치, 특전으로 바뀐 수치, 경기에서 관측한 현재 상태를 별도 데이터로 유지합니다. 선택된 특전을 모르면 그 특전의 효과가 적용됐다고 단정하지 않습니다.
3. 현재 체력, 남은 스킬 쿨타임, 충전 개수, 보호/강화 상태는 영상·HUD에서 관측한 증거로 추적합니다. 정적 DB만으로 이를 확정하지 않습니다.
4. 쿨타임 시작 조건·처치 초기화·충전형 구조·특전·중단/취소 예외는 `effect_notes`, `description`, `cooldown.text`를 함께 확인합니다.
5. 피해량은 발당/발사당/총합과 거리 감소를 구분합니다. `numbers` 배열을 곧바로 피해 계산식에 넣지 않습니다. 복합 조건을 해석할 수 없다면 추정 범위 또는 판단 유보를 사용합니다.
6. `review_required`, 미해결 공식 대조, `review_notes`가 있는 수치를 확정적인 진입·생존·처치 가능성 판단의 근거로 사용하지 않습니다.
7. 한 조건의 `official_component_matched`를 영웅·능력 전체에 대한 검증으로 확대하지 않습니다. 나머지 값의 출처는 위키입니다.
8. 피드백에는 “관측 사실 → 해당 조건의 게임 규칙 → 가능한 행동 → 판단의 불확실성”을 구분해 남깁니다. 보이지 않은 적 스킬 상태나 위치를 사실처럼 만들지 않습니다.

## 구현 전 확인할 예시

- 트레이서: 점멸은 기본 3초마다 충전되며 최대 3회입니다. 3초짜리 단일 쿨타임 스킬로만 처리하지 않습니다.
- 디바: 선택된 기본 체력은 역할 고정 메카 형태이고, 파일럿 체력은 별도 `variants`에 있습니다.
- 솜브라: 이 수집본은 2026년 10월 개편 이후의 지원 역할과 `Hotfix`를 포함합니다. 예전 `Hack`을 현재 능력으로 복구하지 않습니다.
- 궁극기: `ultimate_charge_cost`를 초 단위 재사용 대기시간으로 바꾸지 않습니다.
- 로드호그 `Hogdrogen Exposure`, 독트린 `Deliverance`: 검토 목록을 먼저 확인합니다.

숫자를 보완할 때는 확인한 새 출처·적용 패치·단위·조건을 같은 형식으로 기록하세요. 모델 기억만으로 빈 값을 채우지 마세요.
